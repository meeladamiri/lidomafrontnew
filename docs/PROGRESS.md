آخرین به‌روزرسانی: 2026-08-21

> این فایل «نقشه‌ی برگشت» پروژه‌ست. اگه یه چت جدید (یا ادامه‌ی همین چت بعد از خلاصه‌سازی خودکار) این پروژه رو باز کرد، خوندن همین یه فایل باید کافی باشه بفهمه دقیقاً کجای کاریم. کد واقعی همیشه توی گیت‌هابه، نه توی تاریخچه‌ی چت — پس اگه مکالمه از دست بره چیزی از دست نمی‌ره.

## ساختار پروژه (فعلی)

همه‌چیز زیر یک پوشه‌ست:

```
Desktop/isnad/lidomatrip/lidomatripnew/
  ├── backend/   → https://github.com/meeladamiri/lidomabacknew   (branch: master)
  └── front/     → https://github.com/meeladamiri/lidomafrontnew  (branch: main)
```

- **`backend`** — Express + TypeScript + Prisma + PostgreSQL. از صفر نوشته شده (Odoo قدیم توش نیست). دیتابیس روی **Liara Postgres، اندپوینت عمومی** (`cho-oyu.liara.cloud:33283`) — نه لوکال.
- **`front`** — همون فرانت‌اند اصلی قدیمی Next.js (مشتری + میزبان)، که قبلاً با Odoo کار می‌کرد. **پنل ادمین هم الان همینجاست**، زیر مسیرهای `/admin/*` (قبلاً یه پروژه‌ی جدا به اسم `lidoma-admin` بود — ادغام شد تا از ۳ سرور/۳ ریپو به ۲ برسیم).

هیچ‌کدوم پروداکشن دیپلوی نشدن — فعلاً فقط dev محلی (`npm run dev` توی هر دو پوشه، بک‌اند پورت ۴۰۰۰، فرانت پورت ۳۰۰۰).

### دسترسی تست
- میزبان تستی: `09121111111` / رمز `Host123456!` (isHost: true)
- ادمین تستی: `09120000000` / رمز `ChangeMe123!`
- OTP واقعاً پیامک نمی‌شه (سرویس پیامکی وصل نیست) — کد فقط توی لاگ ترمینال بک‌اند چاپ می‌شه (`[OTP][DEV] ... Code for ...`)

## تصمیمات معماری کلیدی (باید رعایت بشه)

1. **Reshape در لایه‌ی API، نه دست‌کاری کامپوننت‌ها.** هیچ‌کدوم از کامپوننت‌های UI فرانت (حتی ویزارد ۴۲ فایلی ثبت اقامتگاه) دست‌خورده نشدن. هر فایل `api/*.ts` پاسخ REST جدید رو می‌گیره و دقیقاً به شکل envelope قدیمی (`{status, params:{...}}`) reshape می‌کنه.
2. **فیلدهای غایب همیشه default امن** (`[]`، نه `undefined`) — چون کد قدیمی جاهایی بدون optional chaining `.map()`/`.filter()` می‌زنه.
3. **قابلیت‌هایی که بک‌اند معادل نداره** (رزرو اتاق بوم‌گردی، ویرایش رزرو، کد تخفیف): `Promise<any>` که `{status:"error", err_msg:"..."}` برمی‌گردونه — نه crash، نه silent fail.
4. **بعد از هر تغییر: `npx tsc --noEmit` توی هر دو پروژه باید صفر خطا بده.** این تنها verification قابل‌اتکاست چون تست مرورگر غیرقابل‌اعتماده.
5. **قبل از commit به `front`**: چک کن `yarn.lock` توسط `npm install` خراب نشده (این سیستم yarn نصب نداره؛ برای نصب پکیج از `npx yarn@1.22.19 add ...` استفاده کن، نه `npm install`، وگرنه لاک‌فایل به‌هم می‌ریزه).
6. Object storage (`middleware/upload.ts`): اگه env vars ی Liara ست نباشن، خودکار می‌ره سراغ دیسک محلی — همون الگوی «بدون کانفیگ گریسفول دیگرید کن» که برای SMS provider هم استفاده شده.

## چی هنوز مونده (اولویت‌بندی‌شده)

1. **مهاجرت داده‌ی واقعی از Odoo قدیم** — بزرگ‌ترین آیتم. متوقف مونده، منتظر تصمیم شما درباره‌ی نحوه‌ی دسترسی به دیتابیس/API اودو.
2. **سرویس پیامکی واقعی** — کلید API نداریم، فقط کد OTP رو لاگ می‌کنه.
3. **پروفایل کامل کاربر** — ویرایش اطلاعات، آپلود آواتار.
4. **بنر/محتوای CMS صفحه‌ی اصلی و فوتر** — نه مدل دیتابیس داره نه پنل مدیریت (زیرساخت آپلودش الان آماده‌ست، فقط قابلیت نیست).
5. **نقش «کارشناس» جدا از ادمین کامل** — فعلاً فقط دو نقش `USER`/`ADMIN` هست.
6. **صفحه‌ی جزئیات رزرو/کاربر توی پنل ادمین** — فعلاً فقط لیسته.
7. **بوم‌گردی سطح-اتاق** (رزرو/قیمت‌گذاری per-room) — نیاز به تغییر معماری فرانت (الان با پیام خطای تمیز مسدوده، نه crash).
8. **نظرات و امتیازها** — اصلاً مدل نشده (Phase 2).
9. **کیف پول، تسویه میزبان، چت رزرو، شکایات، ووچر** — Phase 2، هیچ‌کدوم ساخته نشده.
10. **صفحه‌ی عمومی پروفایل میزبان** — دست‌نخورده.
11. **درگاه پرداخت** — هنوز بررسی نشده وصله یا نه.
12. **دیپلوی روی سرور واقعی** — فعلاً فقط dev محلی.

## دقیقاً کجا متوقف شدیم

آخرین کار: زیرساخت آپلود فایل از دیسک محلی به Liara Object Storage سوییچ شد (bucket: `lidoma-uploads`)، تست کامل شد، commit و push شد (هر دو ریپو تمیزن، چیزی pending نیست).

اگه بخوایم ادامه بدیم، ترتیب طبیعی همون لیست بالاست — آیتم ۱ (مهاجرت داده) بزرگ‌ترینه و نیاز به تصمیم شما داره؛ بقیه رو می‌شه مستقل و به‌ترتیب دلخواه جلو برد.
